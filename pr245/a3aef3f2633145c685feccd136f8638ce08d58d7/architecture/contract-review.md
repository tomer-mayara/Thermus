## Strongest callable contract and L4 decision

Strongest new contract: `TrackedAuditSender.start(destination, event, signal?) → { outcome: Promise<AuditSendOutcome>, settled: Promise<void> }`, used by AuditCollector; saved Test uses the same sender's `send` facade. Concrete review question: can caller cancellation/time-out clear export content while retaining native capacity until settlement, and can every later export attempt use only fresh enabled/captured-revision authority?

Omit L4. The L3 identifies the audit owner, its caller contexts, shared composition, settings dependency and remote destination. Ordered notes explicitly separate capture/snapshot admission, fresh authorization, retry, public outcome and physical settlement; they name shared native admission and separate Test/export bounds. A function-chain drawing would add internal helpers without resolving a remaining question. This omission is not a claim that no production contract changes: many are added against main. `SystemLogSink.writeSystemLog` also materially changes construction; synchronous failure behavior and OTel nonactivation are stated. Test-helper APIs neither create components nor independently trigger L4. No evaluation-only alternative is necessary unless the manager identifies a gap.
