# FS-02: portal and MCP handoff

This change follows FS-01, PR #122, which merged while this PR was prepared.
Its base is `main` with FS-01 included. Signup stays off. The change supplies
no production document bundle, publishes no policy, and changes no production
provider setting.

## Scope

- After activation, use the existing organization selector and return to the
  portal. Existing product users can continue without another agreement or grant.
- Show free access, the configured MCP address, and connection instructions.
  Browser workspace selection does not change the workspace of an MCP token.
- Give users without access a path to signup and retain invitation and support
  guidance. OAuth consent alone must never create an organization or grant.
- Preserve the retained-record barrier for pending, revoked, and uncertain
  activations. Other authorized workspaces remain usable.
- Prove new-user activation through a real Staging browser and MCP client, then
  prove the actual token workspace and isolation for a user with two workspaces.
