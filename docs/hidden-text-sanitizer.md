# Hidden-text sanitizer

`PromptInjectionRemoverSanitizer` removes hidden HTML elements and comments from source HTML. It also removes invisible characters. It does not remove authored marker text outside removed content.

The sanitizer removes invisible characters once. It then makes up to eight removal scans. Each scan parses the full HTML document and resolves supported inline and embedded CSS. It keeps the original styles on surviving source content for the next scan. It also keeps the effective declarations of unchanged visible source tags. An implied wrapper keeps its declarations when unchanged source content identifies it. Thus, removal of a hidden sibling cannot hide retained content through a changed selector match. New elements use current CSS rules, including rules formed by earlier removals. A new hidden ancestor still removes its descendants. Saved declarations apply only to the current invocation. After the last clean scan, the sanitizer clears resolved visible inline style values for Markdown conversion. It preserves findings and warnings for invisible controls in those decoded values, including duplicate document tags. It does not decode another entity layer or change CSS matching for this reporting step.

The sanitizer checks hidden document elements, including `html` and `body` elements with hidden attributes or inline hidden styles. It also visits nested template content. Each scan finds source ranges for hidden elements and comments. The sanitizer removes those ranges and scans the result again. This allows a removal to expose a new hidden element or comment. When it removes a hidden element, it follows the parsed descendants. This includes descendants whose source appears after the element's closing tag. It keeps visible nodes that the parser places outside the hidden element, such as a paragraph before a hidden table. Source ranges keep template wrappers and text outside removed content. They also preserve supplementary characters. The scan count includes the final scan that finds no ranges. If the eighth scan still finds ranges, the sanitizer returns empty HTML and adds the warning `HTML scan limit reached; remaining HTML withheld`. It does not return HTML that it has not checked.

If a parser scan fails, the sanitizer stops and returns empty HTML. It adds the warning `HTML scan failed; remaining HTML withheld` and keeps reports from earlier scans. A parser failure does not count as a hidden element removal.

Before each removal, the sanitizer checks URLs from parsed attributes in document elements and template content. It keeps threat findings and warnings when a later scan removes their source content. A visible flagged URL stays in the HTML. Each finding category and warning reason appears once per invocation. The sanitizer adds each category found in the invocation to `skipped` once and preserves existing context values.

The parser can merge attributes from a duplicate `html` or `body` tag into an existing document element. The sanitizer checks those effective attributes before it reuses saved declarations. It also keeps the duplicate tag's source range. If the document element is hidden, the sanitizer removes that range with its attributes. If the element is visible, its source attributes remain, except for resolved inline styles that must be cleared for Markdown conversion.

Reconstructed formatting elements can share one source tag and have different effective declarations. The scanner saves each copy's declarations with its nearest authored parent. It keeps a saved copy style only when copies with the same parent and source agree. It uses a shared source fallback only when all surviving copies agree. Conflicting keys cannot replace the current cascade result.

The sanitizer rejects HTML larger than 10 MiB in UTF-8 bytes. This behavior does not change ad removal or Markdown conversion.

The scanner resolves effective font sizes and supported transforms for each parsed element. It passes the parent visibility state to descendants, including template content. Zero font size removes text, but keeps visible font-size overrides and images. A preserved 3D parent can have a hidden local plane and a visible child plane. The scanner removes hidden local text and flat descendants while it checks each preserved child plane. A hidden attribute, `display:none`, or an applicable singular transform still removes the complete parsed subtree.

A near-zero effective author font rule also removes nonempty values from text-entry inputs: `text`, `search`, `tel`, `url`, `email`, and `password`. Missing and invalid input types use the text state. Type matching ignores ASCII case only. HTML `input`, `textarea`, `select`, and `button` elements without an effective author font rule keep an unknown default size. A parent font size alone does not prove that their values or labels are hidden. An explicit author font rule, including `inherit`, still applies. Visible and unresolved author fonts, images, and other native input types remain subject to the existing element and transform rules.

Each scan computes new parent visibility state from the effective declarations. Unchanged visible sources retain the declarations saved by the CSS pass. Thus, markup formed by an earlier removal gets the same checks. The scanner uses the original parser mode for CSS font-size rules. It retains the existing table boundaries for input without a doctype. It removes only source ranges owned by hidden parsed nodes, so text moved outside a table by the parser remains visible. The local `agent-input-sanitizer` patch supplies the visibility resolver. It does not replace the scanner or the removal loop.

The scanner records each text token's source range through public parser adapter methods. It joins ranges only when their source offsets are adjacent. Thus, text merged across a table cannot remove the visible cell between its source segments. Character references remain complete.

Offscreen translation hides local text and void replaced elements, including images and input values. It does not by itself hide the complete subtree: a descendant transform can return content to view. The resolver tracks supported pure translations through both flat and preserved descendants. Position or margin declarations on generated boxes make inherited offsets unknown. A parent's perspective also makes a child's projected plane unknown, even when the child is flat. Perspective declarations follow declaration order and `!important`. Mask shorthands participate in the grouping-property cascade. The resolver extracts each validated compound shorthand's image or source and uses `none` when that component is omitted. Deferred values remain unknown. Paint containment from `content-visibility:auto` makes the effective `transform-style` flat. A singularity check removes a complete subtree only when authored matrix values prove that the matrix is not invertible. A nearly singular matrix can still have a visible child in a flat or preserved 3D context, or a visible result after an unresolved transform. For local and accumulated affine matrices, rank loss requires exact proof. The check composes bounded exact matrix, scale, and translation values. This includes matrices with a Z translation or non-planar terms. A rounding allowance or an unresolved exact determinant does not supply that proof. The near-zero projected-axis rule still applies. Projective transforms remain unknown after the check for a singular matrix because the transform origin can change the projected plane. Invalid raw transform syntax cannot replace an earlier valid declaration. Malformed `var()`, `env()`, and `attr()` function signatures are rejected. Valid named deferred functions and their fallbacks remain unknown.

The scanner supplies the element name, namespace, and input type and value to the visibility resolver. The resolver checks local transform applicability from known element defaults and effective display rules. It ignores a non-replaced inline box's own transform, perspective, and preserve-3d effects. Transform checks remain active for inline-block boxes, replaced content, and boxes made block by known positioning, float, or flex/grid rules. The HTML root uses its blockified display. A declared `inline`, `contents`, or table-column display cannot disable its transform. An ordinary HTML `display:contents` wrapper passes the nearest generated box's transform, perspective, offset, and flex/grid context to its descendants. The wrapper keeps its own font-size inheritance through the parsed parent. Its own box transforms and layout offsets do not apply. HTML elements suppressed by effective `display:contents`, including `meter`, `progress`, and replaced elements, are removed, as described in the [CSS Display rules](https://www.w3.org/TR/css-display-3/#unbox-html). A button with `display:contents` keeps its visible label. When the box type is unknown, an authored local transform cannot prove that content is hidden. An absent local transform, or an explicit `none`, `initial`, or `unset` value, is identity. Known inherited offsets and planes remain active. Inherited visibility and other hiding rules remain active.

The CSS pass supports declaration importance, inline precedence, selector specificity, source order, and normalized escapes. Inline checks include nested template content. Embedded stylesheet rules stay outside template content. Unresolved background paint prevents a same-color verdict; independent supported hiding rules still apply. The pass does not fetch external stylesheets or imports. See the README for the supported selectors, declarations, and layout limits.
